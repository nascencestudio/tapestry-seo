# CLAUDE.md: @nascencestudio/tapestry-seo

The source of truth for anyone (human or AI) working in this repo. Read it at the start of every
session and keep it current.

## What it is

SEO for Tapestry sites on StudioCMS ([ADR 0001](docs/decisions/0001-tapestry-seo.md)): an
admin-controlled robots.txt (crawler categories from ai.robots.txt plus our curated list), a page
sitemap from Tapestry's `listPublicPages()`, and (stage 2, next) per-page SEO in Tapestry's editor
with meta tags. Requires the Tapestry plugin. Nascence Studio, MIT.

Sibling checkouts in `/Volumes/T7/www/`: `tapestry/`, `medialibrary/`, `tapestry-playground/` (dev
site and browser tests: `e2e/seo.e2e.mjs`), and this repo. The devlog of record for the whole
project is the playground's; this repo has its own short one.

## Rules

1. **Security first.** pnpm only (never npm/npx/yarn; `pnpm view`). Hardening in `pnpm-workspace.yaml`
   with written reasons. Pin exact versions. New dependencies need a reviewed ADR (this package has
   none at runtime). `pnpm audit` must pass. No Meta libraries.
2. **Untrusted input:** form posts (same-origin, size-limited), stored settings (re-validated on
   read), extra rules (checked line by line), upstream crawler data (validated by the update script
   and the tests). Never fetch crawler data at runtime.
3. **Document everything:** devlog entry each session; decisions as ADRs (`docs/decisions`, 0001+).
4. **Tests with every change**; adversarial for robots/sitemap output. UI changes: keep
   `tapestry-playground`'s `seo` and `a11y` suites passing.

## Gotchas

- StudioCMS's own robots.txt is on by default and is a **static file written at build time**: it
  only shows up in production. The setting is `features.robotsTXT` (top-level is silently ignored).
  `index.ts` throws in `astro:config:done` if `studiocms/robotstxt` is among the integrations.
- StudioCMS serves plugin sitemaps at `/sitemap-<safe name>.xml` (here
  `sitemap-nascencestudio_tapestry_seo.xml`) and lists them in `/sitemap-index.xml`, which robots.txt
  points to.
- ai.robots.txt's fields are free text: categories come from `categoryFor` (+ `CATEGORY_OVERRIDES`),
  operators from `operatorFor` (cuts sentences, URLs → site name); one crawler can appear under two
  spellings (merged: robots.txt is case-insensitive). Applebot and facebookexternalhit stay curated
  (search / link previews), though ai.robots.txt lists them.
- The settings page is long: keep space below Save (Astro's dev toolbar covers the bottom edge in
  dev; e2e clicks wait until a target is uncovered).
- `usePluginData()` can't save in StudioCMS 0.6.1: use `SDKCoreJs.dbService.db` (settings-store.ts).
